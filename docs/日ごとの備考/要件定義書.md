# 要件定義書 ― 日ごとの備考（メモ）

- 案件名: 日ごとの備考
- 作成日: 2026-11-18
- フェーズ: Spec（OpenSpec なし。成果物はこのフォルダの Markdown）
- 対象リポジトリ: wizway-kintai-demo

## 機能概要 / 目的

ダミー社員の勤怠の1日に、短い備考（メモ）を付けて保存・表示できるようにする。  
出張先や遅刻理由など、区分・時刻だけでは残らない一言を、その日の入力画面で扱う。

## 前提

- 既存のログイン、自分／管理者の権限、月の日ごと表示、1日の保存の流れは維持する
- データは同梱 SQLite（と学習用の共有 DB 更新）に置く。DynamoDB・RDS・本番勤怠は使わない
- 実在の社員名・給与・住所・生年月日は扱わない
- 画面の利用者向け文言は日本語

## 対象外

- CSV 出力への備考列の追加
- 備考だけの単独 API（備考専用の GET／PUT）
- 備考の全文検索、フィルタ、並び替え
- 画像・ファイル添付
- 備考の承認フロー
- 合計（出勤日数・実働・超過・退勤なし件数）の計算への組み込み
- OpenSpec の change／specs への登録（この案件では `docs/日ごとの備考/` に残す）

## 用語

| 用語 | 意味 |
|------|------|
| 備考 | その日に付ける短い自由記述。API・DB 上の項目名は `note` |
| 1日の保存 | 既存の `PUT .../days/{date}`。区分・出勤・退勤・休憩に加え、備考も同じ保存で送る |

## ユースケース（正常系）

### UC1: 備考を付けて1日を保存する

1. ログインした本人（または管理者）が、対象社員の月の日ごと画面を開く
2. ある日の区分・時刻を入力し、備考に文字列を入れる
3. その日を保存する
4. 保存は成立し、同じ月を読み直すと、その日の備考が保存した内容で見える

### UC2: 備考を空にして保存する

1. 備考が付いている日、または空の日について、備考を空文字にして保存する
2. 保存は成立し、その日の備考は空になる

### UC3: 空の日を新規保存するときに備考も入れる

1. まだ保存されていない日に、区分・時刻・備考を入れて保存する
2. 行が作られ、備考も一緒に残る

### UC4: 編集履歴に備考の前後が出る

1. 備考付きの日を、別の備考（または空）に変えて保存する
2. その日の編集履歴に、変更前と変更後の備考が分かる形で残る

## UI 要件

- 日ごとの表に「備考」列を出す
- 各日の備考は、区分・出勤・退勤・休憩と同じ行で編集できるテキスト入力とする
- 入力の `aria-label` は `{日付} 備考` とする（例: `2026-11-02 備考`）
- 備考が長いときの折り返しや専用ダイアログは求めない。1行入力でよい
- 保存ボタン・保存中表示・保存拒否の日本語表示は、既存の1日保存と同じ扱いとする
- 管理者でない人が自分以外の日を開けない制約は、既存どおり変えない

## API 要件

### 月の日ごと取得（既存 GET）

- 各日の行に `note`（文字列）を含める
- 行が未保存の日、または備考が無い日は `note` を空文字 `""` とする
- 既存の `category` / `clock_in` / `clock_out` / `break_time` / `stored` / 編集履歴の扱いを壊さない

### 1日の保存（既存 PUT）

- リクエスト JSON に、既存4項目に加えて `note` を必須とする（キー欠落は拒否）
- `note` の値は文字列とする。`null` は空文字と同じ扱いとしてよい
- 区分・時刻の既存バリデーションは維持する。備考の内容で区分・時刻の可否は変えない
- 保存が成立した応答にも、保存後の `note` を含める
- 権限（未ログイン 401、他人かつ非管理者 403）は既存どおり

### 編集履歴

- 成立した保存では、変更前・変更後の備考も記録に残す
- 月の日ごと取得で返す編集履歴に、前後の備考が分かる情報を含める
- 画面の履歴文言は、備考の変化が分かる日本語にする（区分・時刻だけのときと、備考も変わったときの両方）

## 例外・分岐

| 条件 | 期待 |
|------|------|
| `note` キーが無い | 保存不成立。行は変えない。日本語で、区分・出勤・退勤・休憩・備考をすべて送るよう出す |
| `note` が文字列でない | 保存不成立。行は変えない。形式不正の日本語メッセージ |
| `note` が 100 文字を超える | 保存不成立。行は変えない。日本語で、備考は100文字以内にするよう出す |
| 区分・時刻が既存ルールで不正 | 既存どおり拒否。備考の有無に関わらず行は変えない |
| 未ログイン／権限不足 | 既存どおり 401／403。行は変えない |

文字数は、Unicode のコードポイント数（Python の `len(str)` と同じ数え方）で 100 以下とする。  
改行を含む文字列は、そのまま保存してよい（改行禁止にはしない）。ただし画面は1行入力でよい。

## データ

- `attendance_rows` に備考を保持する
- 初期シードの既存行は、備考を空として扱えること
- 共有 DB を含む既存ファイルに列が無い場合でも、デモとして備考が使えるよう揃えること（具体的な移行手段は Plan）

## 非機能

- 合計計算・CSV・演習用テーブル（`leave_*` 等）の契約は変えない
- SAM の `template.yaml` を大きくしない（新リソースを足さない）
- 利用者向けエラーに英語の理由コードだけを出さない（既存方針）

## テスト観点（概要）

- 備考ありで保存 → 再取得で同じ文字列
- 備考を空に更新できる
- 101 文字は拒否され、行が変わらない
- `note` 欠落は拒否
- 月取得の未保存日は `note` が `""`
- 編集履歴に備考の前後が残る
- CSV の列構成は変わらない（備考列が無い）
- 権限エラー時は備考も書き込まれない

## 受け入れの目安

1. サンプル海原でログインし、空の日に通常出勤と備考「客先A」を保存できる
2. 月を読み直すと、その日の備考に「客先A」が出る
3. 備考を消して保存すると空になる
4. 101 文字の備考は保存できず、日本語の直し方が出る
5. 管理者で他人の日の備考を変えられる（既存の管理者権限の範囲）

## 確定事項（Spec で固定）

1. API／DB 項目名は `note`。画面ラベルは「備考」
2. 最大 100 文字。空文字は可。キーは PUT で必須
3. CSV には出さない
4. 編集履歴には備考の前後を残す
5. 合計・CSV・演習用表・OpenSpec 登録はこの案件の対象外
