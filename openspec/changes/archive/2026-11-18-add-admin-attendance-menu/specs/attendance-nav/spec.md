# Spec Delta

## Purpose

ログインした人には自分の月を出し、左メニューから移動する。全員の勤怠は管理者だけが開き、管理者でない人は自分以外の日を読めず、更新もできない。

## ADDED Requirements

### Requirement: ログイン後は自分の月を出す

ログインが成立したとき、画面は、その人の指定月の日ごとの入力を出さなければならない（SHALL）。3人の合計を、最初の画面に出してはならない（MUST NOT）。

#### Scenario: サンプル海原の最初の画面は自分の月

- **GIVEN** ログイン画面を開いている
- **WHEN** サンプル海原を `unahara` でログインする
- **THEN** サンプル海原の 2026-11 の日ごとの入力が見える
- **AND** 2026-11-02 の出勤は 09:00、退勤は 18:00 である
- **AND** 3人の合計は見えない

#### Scenario: デモ管理の自分の月は空である

- **GIVEN** ログイン画面を開いている
- **WHEN** デモ管理を `kanri` でログインする
- **THEN** デモ管理の 2026-11 の日ごとの入力が見える
- **AND** 2026-11-02 は保存済みでない
- **AND** 出勤日数は 0 である

### Requirement: 左メニューで自分の勤怠と全員の勤怠を分ける

ログイン中の画面は、左メニューを出さなければならない（SHALL）。メニューに「自分の勤怠」を出さなければならない（SHALL）。管理者のときだけ「全員の勤怠」を出さなければならない（SHALL）。管理者でない人のメニューに「全員の勤怠」を出してはならない（MUST NOT）。

#### Scenario: サンプル海原のメニュー

- **GIVEN** サンプル海原でログインしている
- **WHEN** 左メニューを見る
- **THEN** 「自分の勤怠」がある
- **AND** 「全員の勤怠」は無い

#### Scenario: デモ管理は全員の勤怠を開ける

- **GIVEN** デモ管理でログインしている
- **WHEN** 「全員の勤怠」を押す
- **THEN** 2026-11 の3人の合計が見える
- **AND** 各行に「日ごとを入力」がある
- **AND** その画面に、日を保存する操作は無い

#### Scenario: 全員の勤怠から日ごとを入力する

- **GIVEN** デモ管理が 2026-11 の全員の合計を見ている
- **WHEN** 社員2の行で「日ごとを入力」を押す
- **THEN** 社員2の 2026-11 の日ごとの入力が見える
- **AND** 2026-11-02 の出勤は 09:00、退勤は 18:00 である

### Requirement: 自分以外の日は管理者だけが扱う

管理者でないセッションで、システムは自分以外の社員の月の行、合計、全員の合計、CSV、日の更新を成立させてはならない（MUST NOT）。日本語で、管理者だけが見られると出さなければならない（SHALL）。行を変えてはならない（MUST NOT）。管理者のセッションでは、勤怠の3人の月を読み、更新できなければならない（SHALL）。

#### Scenario: サンプル海原はテスト青空の日を更新できない

- **GIVEN** 社員1の 2026-11-02 は退勤 18:00 である
- **WHEN** サンプル海原でログインし、その日の退勤を 19:00 にして更新しようとする
- **THEN** 更新は成立しない
- **AND** その日の退勤は 18:00 のままである
- **AND** 管理者だけが見られる、と出る

#### Scenario: サンプル海原は全員の合計を受け取れない

- **GIVEN** サンプル海原でログインしている
- **WHEN** 2026-11 の全員の合計を要求する
- **THEN** 一覧は返らない
- **AND** 管理者だけが見られる、と出る

#### Scenario: デモ管理は他人の日を保存できる

- **GIVEN** 社員1の 2026-11-02 は退勤 18:00 である
- **WHEN** デモ管理でログインし、その日の退勤を 19:00 にして更新する
- **THEN** 更新は成立する
- **AND** その日の退勤は 19:00 である
- **AND** その記録の入力者はデモ管理である

### Requirement: ログイン画面に管理者のパスワードを出す

ログイン画面のパスワードの表に、デモ管理と `kanri` を出さなければならない（SHALL）。`kanri` でログインは成立しなければならない（SHALL）。応答にパスワードを含めてはならない（MUST NOT）。

#### Scenario: 表に4人いる

- **GIVEN** 画面を開いた
- **WHEN** まだログインしていない
- **THEN** テスト青空、サンプル海原、見本山辺、デモ管理と、それぞれのパスワードが見える
- **AND** デモ管理のパスワードは `kanri` である
- **AND** 3人の合計は見えない
