# 変更提案

## なぜ

ログインしたあとも、3人の合計が先に出る。普通の勤怠なら、開くのは自分の月である。全員が見えるのは管理者で、そこへ行く入口は左メニューである。

## 背景

いまの画面は、ログインすると3人の合計が出る。「日ごとを入力」で、ログインした人以外の日も開ける。保存の入力者は、ログインした人である。ダミー社員は3人で、管理者はいない。

`add-demo-login` は実装済みで、まだ正本へは反映していない。この変更は、そのログインの上に載せる。

## 目的

ログイン後の最初の画面を、その人の月にする。左メニューに「自分の勤怠」を置く。管理者だけ「全員の勤怠」を出し、そこから今の3人の合計と、日ごとの入力へ移る。

## 変更内容

- **BREAKING** ログイン直後に3人の合計を出さない。自分の月を出す
- 左メニューを出す。「自分の勤怠」はログインした人なら誰でも使える
- 管理者を1人足す。その人だけ「全員の勤怠」が見える
- **BREAKING** 管理者でない人は、自分以外の月の読み取りと更新ができない
- 全員の合計と、月の CSV は、「全員の勤怠」にある
- ログイン画面の表に、管理者の表示名とパスワードを足す

## 対象能力

### 新規の能力

- `attendance-nav`: ログイン後は自分の月を出し、左メニューで移動する。全員の勤怠は管理者だけが開く

### 変更する能力

- `attendance-overview`: 全員の合計は、管理者のセッションがあるとき返す。最初の画面には出さない
- `attendance-month`: 社員一覧は、管理者には勤怠の3人、本人には自分だけを返す
- `attendance-edit-log`: 他人の日を残せる入力者は、管理者である

## スコープ

- 管理者は4人目。表示名は デモ管理、パスワードは `kanri`。ログイン画面の表に出す
- 勤怠の対象は今の3人のまま。デモ管理の行は初期データに作らない
- 左メニューは「自分の勤怠」と、管理者だけの「全員の勤怠」
- ログアウトは、今どおりログイン中の表示のそばに出す
- 他人の日を管理者が保存したとき、記録の入力者はデモ管理である
- 本番勤怠リポジトリと本番 AWS アカウントは変更しない。デプロイ先は学習用アカウントのみ

## 非スコープ

- 管理者を3人の中から選ぶこと
- パスワードの変更、再設定、メール、連続失敗でのロック
- 管理者以外の権限の差
- 左メニューに、勤怠以外の項目を足すこと
- DynamoDB、RDS、コンテナの常時起動
- 実在の社員名、給与、住所、生年月日
- 学習パックのコース本文。公開 URL が変わらない限り導入メモも更新しない

## リスク

- `add-demo-login` を正本へ反映する前にこの変更を反映すると、「ログイン後は3人の合計」が戻る
- 既存のテストは、社員2が社員1の日を更新できる前提がある。管理者でないとその更新は失敗する
- 共有ファイルに管理者がいないときは、開いたときに行を残したまま管理者を足す

- `frontend/src/App.tsx` の左メニューと、最初の画面
- `backend/tests` と `tests/e2e/attendance.spec.ts`
