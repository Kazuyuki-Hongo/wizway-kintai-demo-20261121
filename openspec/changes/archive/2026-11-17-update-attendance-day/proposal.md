# Proposal

## Why

読み取り専用の勤怠デモは、月の行と合計を返すだけで、仕様の Scenario が状態の変化と入力の拒否を持てない。学習パックで「change を分けて仕様を固定してから実装する」見本にするには、既存の日を更新でき、月の空いている日が見える必要がある。

## 背景

`demo-kintai` は archive 済みで、`attendance-month` と `attendance-summary` が main spec にある。API は GET のみ、SQLite は読み取り専用、画面に保存は無い。社員1の 2026-11 は 4 行だけで、月の残りの日は返らない。

## 目的

ダミーのまま、保存済みの1日を更新できるようにする。更新の拒否条件を仕様の Scenario にする。指定月は、行が無い日も含めてカレンダーの全日を返す。実働の合計は、これまでどおり SQL の結果を読む。

## What Changes

- 保存済みの1日について、区分・出勤・退勤・休憩をまとめて更新する
- 拒否する入力（時刻の前後、休憩の過大、欠勤なのに時刻がある、時刻形式、年月、社員、保存済みでない日）では、行を変えない
- **BREAKING** 指定月の勤怠行は、その月の各日を返す。保存済みでない日は区分と時刻が空で、保存済みと区別できる
- 更新が成功したあとの合計は、保存後の行を材料に SQL で計算し直した値になる
- 保存した値は、同じ実行環境の次の読み取りに現れる。実行環境が初期データからやり直したあとは、保存前の値に戻る

## Capabilities

### New Capabilities

- `attendance-day-update`: 保存済みの1日を更新する。拒否したときは行を変えない

### Modified Capabilities

- `attendance-month`: 指定月はカレンダーの全日を返す。保存済みでない日を含む。読み取りは、更新後の保存内容を返す
- `attendance-summary`: 合計は更新後の保存済み行だけを材料にする。保存済みでない日は材料にしない

## スコープ

- 区分は `通常出勤` と `欠勤` のまま。通常出勤は出勤が必須で、退勤が空の行は残せる。欠勤は時刻を空にする
- 時刻は同一日の `HH:MM`（00:00〜23:59）。日付をまたがない
- 更新は、その社員・その日の行が既にあるときだけ成功する。行が無い日は表示し、この change では作らない
- 1回の更新は、その日の区分と時刻をすべて送る
- ログインは無い

## 非スコープ

- 行が無い日への新規作成、欠勤の新規登録、行の削除
- 有休、休日出勤、深夜、日付をまたぐ時刻、月締め、承認
- 本番勤怠リポジトリ `wizway_kintai`、本番 URL、本番 DB、開発 VM、本番の勤怠と同じ AWS アカウントへのデプロイ
- DynamoDB、RDS、常時起動コンテナ。データファイルの正本を S3 に移すこと
- 実在の社員名、給与、住所、生年月日
- コース本文への追記。見本 URL が変わらない限り、導入メモも変えない

## リスク

- Lambda の配置物は更新できない。実行環境のコピーに書くため、冷えたあとは同梱の初期データに戻る。公開 URL では、別の実行環境に当たると保存が見えない
- 月の応答が保存済み行だけから全日になる。既存の画面とテストは、行数と空日の前提を変える
- 本番勤怠のアカウントへデプロイすると、既存スタックに影響する

## Impact

- `sql/` の月次 SELECT、`backend/` の更新 API、`frontend/` の編集、`template.yaml` の PUT、`backend/tests/` と `tests/e2e/`
- 本番勤怠の OpenSpec、ソース、AWS アカウントは変えない
