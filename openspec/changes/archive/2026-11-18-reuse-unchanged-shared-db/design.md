# 設計

## 前提

新しいリポジトリは作らない。対象は既存の `wizway-kintai-demo`。

| 層 | 置き場 |
| --- | --- |
| 画面 | `frontend/`。この変更では触らない |
| API | `backend/app.py`。共有ファイルの取得と書き戻し |
| SQL | `sql/` と `backend/sql/`。この変更では触らない |
| AWS | 既存の Lambda と、非公開バケット `DemoDbBucket`。環境変数は `KINTAI_DB_BUCKET` と `KINTAI_DB_KEY`。リソースは足さない |

動機は [proposal.md](proposal.md) の「なぜ」。いまの取得は `_prepare_shared_db` がリクエストごとに `download_file` で `/tmp/attendance.db` を上書きする。書き戻しは `_publish_shared_db` で、日の保存、ログイン、ログアウトの成功後に呼ばれる。ローカルと pytest は `KINTAI_RUNTIME_DB` があり、S3 を呼ばない。

実装は `.cursor/skills/openspec-apply-change/SKILL.md` に従う。Serena のプロジェクトルールは `docs/rules/project-rules-serena.md`。

## 目標 / 対象外

**目標:**
- 共有オブジェクトの ETag が同じあいだ、中身の GET をしない
- ETag が変わった次の読み取りは、その中身を返す
- 書き戻しが成功した実行環境は、新しい ETag を覚える
- 書き戻しが失敗した実行環境は、次の読み取りで S3 の中身を取り直す

**対象外:**
- 一定時間 S3 を見ないこと
- 保存時の If-Match による先勝ち
- Lambda のメモリ、画面の呼び出し回数、スキーマ確認の回数

## 決定事項

### 1. 変わったかは条件付き GET で見る

実行環境は、最後に見た ETag をプロセス内に持っておく。次の取得は `If-None-Match` 付きの GET にする。304 なら `/tmp` のファイルを使う。200 なら中身を取り直す。オブジェクトが無いときは、今どおり同梱の初期データをアップロードしてから使う。

HEAD のあとで GET する案は取らない。変わったときに往復が2回になる。

ETag は S3 が返す値をそのまま覚える。引用符を外して比較し直さない。

代替として数秒 `/tmp` を信じる案は、proposal の非スコープなので取らない。

### 2. 中身は別ファイルに書いてから置き換える

200 の本体は `/tmp/attendance.db` へ直接書かない。一時ファイルに書き、置き換えが終わってから ETag を更新する。途中で失敗したときは、覚えていた ETag とそれまでの `/tmp` を残す。

テストは Lambda の `/tmp` に依存しない。取得先のパスを差し替えられるようにし、S3 クライアントも差し替える。

### 3. クライアントは実行環境で1つ

boto3 の S3 クライアントは、その実行環境の最初の利用で作り、以降はそれを使う。リクエストごとに作り直さない。

### 4. 書き戻しの成功と失敗で ETag の扱いを分ける

`_publish_shared_db` が成功したあと、HEAD で新しい ETag を読んで覚え直す。日の保存だけでなく、ログインとログアウトもこの関数を通る。

書き戻しが失敗したときは、覚えていた ETag を消す。次の読み取りは条件を付けずに S3 から取り直す。失敗した保存の内容を、その実行環境だけが次の GET で返し続けないようにする。

保存同士の上書きは今のまま後勝ちにする。If-Match は付けない。

### 5. ローカルと pytest の既定は S3 を呼ばない

`KINTAI_RUNTIME_DB` があるときは、今どおりそのファイルだけを開く。既存の `backend/tests/test_api.py` はこの経路のままにする。条件付き GET の確認は、クライアントと取得先を差し替えた別のテストにする。

## リスク / トレードオフ

- [覚えていた ETag と S3 がずれる] → 失敗時は ETag を消し、次の読み取りで取り直す。成功時は HEAD の値で覚え直す
- [取り直しの途中で `/tmp` が壊れる] → 別ファイルに書いてから置き換える。置き換え前に失敗したら ETag は更新しない
- [同じ実行環境に同時のリクエストは来ない前提] → Lambda の実行環境は1リクエストずつなので、ETag 用のロックは置かない
- [待ちは残る] → 画面は API を複数回呼ぶ。128MB のままである。2回目以降の中身の GET が無くなるだけである

## 移行手順

リソースとオブジェクトの形は変えない。Lambda のコードだけを載せ替える。

1. `aws sts get-caller-identity --profile deploy-jisseki` のアカウントが `655129713987` であることを確認する
2. プロファイル `deploy` とアカウント `023194178508` は使わない。本番勤怠のリポジトリと、本番の勤怠と同じ AWS アカウントには出さない
3. スタック `wizway-kintai-demo` の Lambda だけを更新する
4. 公開 URL で、デモ管理の個別の勤怠がテスト青空の 2026-11 を返すことを確認する。確認で共有ファイルを変えたら、保存した行が次の読み取りに残っていることだけ見て、初期データへ戻す作業はしない

戻すときは、前の Lambda コードを同じ学習用アカウントへ載せる。S3 のオブジェクトはそのまま使える。
