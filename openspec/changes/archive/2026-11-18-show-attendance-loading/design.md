# Design

## Context

待ちの文は、画面 `frontend/src/App.tsx` に無い。ログイン、日ごとと合計の取得、保存、CSV は、応答が返るまでボタンの文を変えない。API、SQL、SAM はこの変更で触らない。新しいリポジトリは作らない。

実装手順の正本は `.cursor/skills/openspec-apply-change/SKILL.md`。Serena の約束は `docs/rules/project-rules-serena.md`。挙動を変えるので、適用時は OpenSpec と Serena を使う。

## Goals / Non-Goals

**Goals:**

- 押した操作のボタン、またはその画面の本文に、待ちの文を出す
- 同じ操作の連打で通信を増やさない
- 月を切り替えているあいだ、前の月の日を保存できないようにする
- 左メニューは隠さない

**Non-Goals:**

- 共有ファイルの取り直しを減らすこと
- 日ごとと合計を1つの API にまとめること
- 待ちの文を全面の覆いで出すこと

## Decisions

待ちの文は、今のボタンと本文に出す。ログインはボタンを「ログインしています」、保存はその日のボタンを「保存しています」、CSV は「出しています」にする。日ごとや全員の合計がまだ無いあいだは、本文に「読み込んでいます」と出す。通信中は、そのボタンを押せないようにする。新しい部品やライブラリは足さない。

月を変えたとき、前の月の行が残っていても、保存のボタンは出さない。届いた月の行に替わってから、保存できるようにする。遅い応答が後から届いても、いま選んでいる月と違う結果では表を替えない。応答を始めたときの月と画面を覚えておき、今と違うなら捨てる。

保存が成立したあとに取り直す日ごとも同じである。取り直しを始めたときの月と社員を覚え、今の画面と違う応答では行を入れない。保存中に月を変えたときは、更新は元の月に残り、今の表は変えたあとの月のままにする。

E2E で待ちの文を見るときは、その通信の応答を遅らせる。遅らせない既存の確認は、結果の文と値を見る。待ちの文が残っていることは求めない。

デプロイは画面だけである。API の `sam deploy` はしない。先に `aws sts get-caller-identity --profile deploy-jisseki` でアカウントが `655129713987` であることを確認する。プロファイル `deploy` とアカウント `023194178508` は使わない。フロントはバケット `wizway-kintai-demo-frontend-655129713987` へ置き、CloudFront `E1N0VGUC7GMMK5` を無効化する。公開 URL は変えない。

## Risks / Trade-offs

- [応答が速いと待ちの文は一瞬で消える] → 待ちの文を見る E2E だけ、応答を遅らせる
- [古い応答が新しい月の表を上書きする] → 始めたときの月と違う応答は捨てる
- [保存中に月を変える] → 読み込み中は保存のボタンを出さない。進行中の保存が成立したら、その結果は元の月に残る。成立後の取り直しは、今の月の表を上書きしない

## Migration Plan

画面のビルドを学習用アカウントのフロントバケットへ置く。API と共有ファイルは変えない。戻すときは、前の画面のビルドを同じバケットへ戻す。
