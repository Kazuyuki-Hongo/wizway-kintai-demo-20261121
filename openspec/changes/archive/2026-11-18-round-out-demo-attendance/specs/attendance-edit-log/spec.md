# Spec Delta

## Purpose

成立した1日の保存について、誰が、どの日を、何から何へ変えたかを残し、その日の入力画面に新しい順で出す。

## ADDED Requirements

### Requirement: 成立した保存を1件残す

保存が成立したとき、システムは記録を1件足さなければならない（SHALL）。記録は、入力者、対象の社員、日付、変更前の区分と出勤と退勤と休憩、変更後の区分と出勤と退勤と休憩を含まなければならない（SHALL）。給与、住所、生年月日を含めてはならない（MUST NOT）。

#### Scenario: 別の社員が有休に変える

- **GIVEN** 社員1の 2026-11-02 は通常出勤、出勤 09:00、退勤 18:00、休憩 01:00 である
- **AND** その日の記録は無い
- **WHEN** 入力者を社員2にして、その日を有休、出勤、退勤、休憩を空にして更新する
- **THEN** その日の記録が1件ある
- **AND** 入力者は社員2である
- **AND** 対象は社員1である
- **AND** 日付は 2026-11-02 である
- **AND** 変更前は通常出勤、出勤 09:00、退勤 18:00、休憩 01:00 である
- **AND** 変更後は有休で、出勤、退勤、休憩は空である

#### Scenario: 空の日の保存は変更前が空である

- **GIVEN** 社員1の 2026-11-21 は保存済みでない
- **WHEN** 入力者を社員1にして、その日を通常出勤、出勤 09:00、退勤 18:00、休憩 01:00 に更新する
- **THEN** その日の記録が1件ある
- **AND** 変更前の区分と時刻は空である
- **AND** 変更後は通常出勤、出勤 09:00、退勤 18:00、休憩 01:00 である

### Requirement: 入力者が無い更新は対象の社員として残す

更新に入力者が無いとき、システムは対象の社員を入力者として記録しなければならない（SHALL）。更新そのものは、入力者が無くても、他の条件を満たせば成立させなければならない（SHALL）。

#### Scenario: 入力者を送らない

- **GIVEN** 社員1の 2026-11-02 が保存済みである
- **WHEN** 入力者を送らず、その日を通常出勤、出勤 10:00、退勤 19:00、休憩 01:00 に更新する
- **THEN** 更新は成立する
- **AND** その記録の入力者は社員1である

### Requirement: 拒否した保存は記録しない

保存が成立しないとき、システムは記録を足してはならない（MUST NOT）。

#### Scenario: 退勤が出勤より前

- **GIVEN** 社員1の 2026-11-02 の記録は無い
- **WHEN** その日の退勤を出勤より前にして更新しようとする
- **THEN** 更新は成立しない
- **AND** その日の記録は無い

### Requirement: その日の記録だけを新しい順に出す

日ごとの入力は、開いている社員と日付の記録だけを、新しいものが先に出さなければならない（SHALL）。別の日の記録を、その日の画面に出してはならない（MUST NOT）。

#### Scenario: 同じ日を2回保存すると新しい方が先

- **GIVEN** 社員1の 2026-11-02 を、入力者社員2が有休に更新した記録がある
- **WHEN** 続けて、入力者社員3が、その日を通常出勤、出勤 09:00、退勤 18:00、休憩 01:00 に更新し、その日の入力を開く
- **THEN** 先に見える記録の入力者は社員3である
- **AND** その次の記録の入力者は社員2である

#### Scenario: 別の日の記録は出ない

- **GIVEN** 社員1の 2026-11-02 に記録がある
- **WHEN** 社員1の 2026-11-03 の入力を開く
- **THEN** 2026-11-02 の記録は見えない
