# Design

## Context

動機は proposal.md の Why。仕様の差分は、この change の `specs/` にある。

リポジトリは `wizway-kintai-demo`。画面は `frontend/`（React + TypeScript）。API は `backend/app.py`（Python Lambda）。合計の式は `sql/month_summary.sql` と、同内容の `backend/sql/month_summary.sql`。表定義は `sql/schema.sql`。同梱の初期データは `sql/build_db.py` が `backend/data/attendance.db` を作る。公開中の共有ファイルは、学習用アカウントの非公開 S3 にある `attendance.db`。各リクエストがダウンロードし、保存が成立したときだけ書き戻す。

区分の制約は今、`通常出勤` と `欠勤` だけである。合計 SQL は通常出勤だけを出勤日数に入れる。PUT の本体は区分、出勤、退勤、休憩の4つ。入力者は無い。

実装に入る前に、Serena MCP（namespace は `user-serena`）で `initial_instructions` を呼ぶ。失敗したらコードを編集しない。手順の正本は `.cursor/skills/openspec-apply-change/SKILL.md`。Serena の詳細は `docs/rules/project-rules-serena.md`。

## Goals / Non-Goals

**Goals:**

- 半休と有休を保存でき、合計は SQL のまま数える
- 成立した保存だけ記録し、その日の行の下に出す
- 一覧からその月の CSV を出す
- すでに共有ファイルにある行を消さずに、表を広げる

**Non-Goals:**

- パスワードとセッション
- 合計を Python で計算し直すこと
- 公開 URL の変更

## Decisions

### 1. 共有ファイルは起動時に広げる

`attendance.db` を開いたあと、次を行う。テストが使う `KINTAI_RUNTIME_DB` も同じ。

- `attendance_edits` が無ければ作る。列は、時刻、入力者の社員 id、対象の社員 id、日付、変更前の区分と3つの時刻、変更後の区分と3つの時刻
- `attendance_rows` の区分制約に半休と有休が無いときは、行をコピーして制約を付け替える。既存の行は残す

代替として、公開時に S3 の `attendance.db` を消して同梱の初期データへ戻す案は取らない。デモで保存した日が消える。

### 2. 合計は SQL の区分条件だけ広げる

`month_summary.sql` の出勤日数、実働、退勤なしは、通常出勤に加えて半休も含める。有休は欠勤と同じく、どの合計にも入れない。式の形は変えない。`sql/` と `backend/sql/` の両方を同じ内容にする。

### 3. 入力者は任意の項目にする

PUT の JSON に `editor_id` を足す。無い、または空のときは、対象の社員 id を入力者にする。1、2、3 以外は日本語で拒否し、行も記録も書かない。画面の初期値は未選択で、未選択のときは通信しない。

代替として、入力者を必須にして既存の成功 Scenario を全部書き換える案は取らない。入力者を送らない更新は、これまでどおり成立する。

### 4. 記録は成立した PUT のあと、共有ファイルを書く前に足す

拒否の戻りでは記録を足さず、共有ファイルも書き戻さない。空の日の変更前は、区分と時刻を空にする。月の読み取りに、その社員の記録を日付つきで足す。画面は各日の行の下に、その日だけを新しい順で出す。

### 5. CSV は一覧用の GET を1本足す

`GET /months/{ym}/export`。`template.yaml` にイベントを足す。応答は `text/csv`、UTF-8、先頭 BOM、`Content-Disposition` のファイル名は `kintai-YYYY-MM.csv`。中身はその月のカレンダー全日を3人分。不正な年月は CSV を返さず、既存と同じくログに `invalid ym=` を残し、画面向けの `reason` は日本語にする。読み取りでは共有ファイルを書き戻さない。

画面の一覧に「この月をCSVで出す」を置く。日ごとの保存ボタンは一覧に置かない。

### 6. 保存できた文は、その日の保存が 200 のときだけ出す

「保存しました」はその日の行に出す。区分や時刻を変えたら消す。拒否のときは出さない。有休を選んだら、欠勤と同じく3つの時刻を空にする。半休は空にしない。

### 7. デプロイは学習用アカウントだけ

プロファイル `deploy-jisseki` で、アカウントが `655129713987` であることを確認してから `sam deploy` する。プロファイル `deploy` と、アカウント `023194178508` は使わない。スタック名は `wizway-kintai-demo`。画面は既存のフロント用バケットへ出す。公開 URL が変わっていなければ、学習パックの導入メモとコース本文は編集しない。

## Risks / Trade-offs

- [制約の付け替えに失敗すると共有ファイルが中途半端になる] → 付け替えは1つのトランザクションで行い、失敗したら書き戻さない
- [半休が1日として数える] → 画面の半休の近くに、実働は入れた時刻から計算する、と1文書く
- [入力者なしの API は対象本人になる] → 画面は未選択で通信しない。API の既定は仕様どおり対象社員
- [CSV は保存済みでない日も出す] → 行数は 2026-11 が 90、2026-02 が 84。テストで固定する

## Migration Plan

1. 表の拡張、合計 SQL、区分、記録、CSV を API に足し、pytest で確認する
2. 画面に成功メッセージ、区分、入力者、記録、CSV を足し、Playwright で確認する
3. アカウントを確認してから、学習用アカウントの API と画面を更新する
4. 公開 URL が変わっていないことを確認する。変わっていなければ導入メモは更新しない
5. 戻すときは、直前の関数と画面の成果物に戻す。共有ファイルの記録表は残してよい。区分制約を古い2値へ戻す作業は、有休や半休の行が無いときだけ行う
