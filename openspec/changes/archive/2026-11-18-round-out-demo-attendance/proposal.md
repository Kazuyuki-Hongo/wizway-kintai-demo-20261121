# 変更提案

## なぜ

保存の拒否は日本語で出るが、保存できたことは出ない。区分は通常出勤と欠勤だけなので、有休にしようとした保存は拒否される。誰が保存したかも残らない。一覧の数字は画面を閉じると持ち出せない。デモとして開いた人が、一般的な画面でまず探す操作が欠けている。

## 背景

`attendance-day-update` は、区分が通常出勤と欠勤以外なら更新を成立させない。有休で更新しようとする Scenario が、その拒否を固定している。合計は SQL が、通常出勤だけを出勤日数に入れ、欠勤は入れない。一覧は3人の合計を先に出し、日ごとの保存は別画面にある。保存の主体は無く、成功時の画面メッセージも無い。データは学習用アカウントの共有 SQLite 1ファイルで、パスワードもセッションも無い。

## 目的

ダミーのまま、次の4つを同じ change で足す。保存できたことを日本語で出す。区分に半休と有休を足し、出勤日数に入れるかどうかを仕様にする。入力者を選ばないと保存できず、成立した保存の前後をその日の横に残す。開いている月の3人分を CSV で出せるようにする。

## 変更内容

- 保存が成立したとき、画面に「保存しました」と出す。拒否のときは出さない
- 区分に半休と有休を足す。有休は時刻を空にし、出勤日数に入れない。半休は通常出勤と同じ時刻規則で、出勤日数には1日として入れ、実働は実時刻から計算する
- **BREAKING** 区分を有休にして更新すると、現行仕様では成立しない。この変更では、時刻が空なら成立する
- 日ごとの画面は、入力者を3人のダミーから選ばないと保存の通信をしない。選んだ入力者で成立した保存だけ、変更前と変更後を記録し、その日の横に新しい順で出す
- 一覧の画面から、その月の3人の全日（空の日を含む）を CSV で出す。給与は含めない

## 対象能力

### 新規の能力

- `attendance-edit-log`: 成立した保存について、入力者、対象、日付、変更前、変更後を残し、その日の横に出す
- `attendance-month-export`: 指定月のダミー社員全員の全日を CSV で出す

### 変更する能力

- `attendance-day-update`: 半休と有休を受け付ける。有休を拒否する要件を、受け取らない区分の例へ置き換える。保存成立の画面メッセージと、入力者未選択では通信しないことを足す
- `attendance-summary`: 有休は出勤日数と実働に入れない。半休は通常出勤と同じ式で出勤日数に1日入れる
- `attendance-overview`: 有休に更新したあと、一覧の出勤日数がその分だけ減る

## スコープ

- 追加する区分は半休と有休だけ。それ以外（出張など）はこれまでどおり拒否する
- 有休は欠勤と同じで、出勤・退勤・休憩は空。出勤日数に入れない。実働に足さない。退勤なしの件数にも入れない
- 半休は通常出勤と同じ時刻規則（出勤は必須、退勤を入れるなら休憩も入れ、休憩は長さで、出勤から退勤までより長くしない）。出勤日数には1日として入れる。実働は実時刻から計算し、4時間には固定しない
- 入力者は画面の選択。未選択のときは「入力者を選んでください」と出し、保存の通信はしない
- 更新リクエストに入力者が無いときは、対象の社員を入力者として記録する。既存の、入力者を送らない成功 Scenario はそのまま成立する
- 記録は保存が成立したときだけ残す。拒否した保存は記録しない
- CSV の列は社員名、日付、区分、出勤、退勤、休憩。その月のカレンダー全日を3人分出す。文字コードは UTF-8（BOM 付き）。ファイル名は `kintai-YYYY-MM.csv`
- 初期データの合計（社員1の 2026-11 が 18 / 137 / 1 / 1 など）は、区分を変える前は今のまま
- 本番勤怠リポジトリと本番 AWS アカウントは変更しない。デプロイ先は学習用アカウントのみ

## 非スコープ

- パスワード、セッション、権限。ログイン画面は作らない
- 月締め、給与、日をまたぐ時刻、承認、通知
- DynamoDB、RDS、コンテナの常時起動
- 実在の社員名、給与、住所、生年月日
- 学習パックのコース本文。公開 URL が変わらない限り導入メモも更新しない

## リスク

- 有休の拒否が成功に変わるため、区分のテストと画面の選択肢を同時に直さないと、古い「有休は拒否」が残る
- 半休を1日として数えるので、見た目の「半日」と出勤日数の1がずれる。仕様と画面の説明で、実時刻で計算すると書く
- 入力者が無い API 更新は対象社員として記録する。画面以外からの保存は、対象本人の操作に見える
- 共有ファイルへの記録が増える。拒否では記録も共有ファイルも更新しない
