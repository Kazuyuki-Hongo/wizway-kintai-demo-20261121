# 変更提案

## なぜ

学習パックで使う勤怠デモの初版が無い。雑メモ見本は画面と API の型だけで、月の一覧と集計があり、仕様駆動と Serena を必須にした見本になっていない。

## 背景

本番の勤怠は PHP と MariaDB で、勤怠表・集計のほかに有休、給与、社員マスタが同じリポジトリにある。学習パック利用者がクローンする見本には、その木を出せない。初版は、勤怠表と集計だけをダミーで別リポジトリに作る。

## 目的

ダミーデータだけの読み取り専用アプリの初版を、別リポジトリで AWS に載せ、学習パック利用者が URL とソースを見られるようにする。初版の実装と、その後の機能追加は OpenSpec と Serena を必須にする。

## 変更内容

- 新規リポジトリ `wizway-kintai-demo` に、ダミー社員の月次勤怠表と、その月の合計を返す API と画面を置く
- 時間の計算は SQL で行う。現行勤怠の PHP 集計は移植しない
- 画面と API の載せ方は雑メモ見本に揃える（React + TypeScript、Python Lambda、API Gateway、S3、CloudFront、SAM）
- データは Lambda に同梱する SQLite。DynamoDB と RDS は足さない
- デプロイ先は実績づくりの学習用アカウント。載った URL を README と学習パックの導入メモに書く
- OpenSpec の apply / propose スキルを、勤怠リポジトリと同様に Serena 未接続なら実装を始めない形へ直す。対象は Python と TypeScript で、PHP と開発 VM の手順はコピーしない

## 対象能力

### 新規の能力

- `attendance-month`: ダミー社員1人分の、指定月の勤怠行を読み取る
- `attendance-summary`: その月の出勤日数、総実働、8時間を超えた分、退勤が無い日の件数を読み取る

### 変更する能力

- なし。このリポジトリに既存の仕様は無い

## スコープ

- ダミー社員は3人。画面は1人の月を選んで見る
- 行は日付、区分（通常出勤または欠勤）、出勤、退勤、休憩
- 通常出勤で退勤が無い行を、シードに1件以上含める
- ログインは無い。誰でも同じダミーを読む
- 不正な年月は 400 とし、ログに理由を1行出す

## 非スコープ

- 本番勤怠リポジトリ `wizway_kintai` の変更、本番 URL、本番 DB、開発 VM
- 本番の勤怠と同じ AWS アカウントへのデプロイ
- 有休、規則、福利厚生、ブログ、共有勤怠、義休、個人設定、社員マスタ、支給、給与、源泉、住民税
- 交通費、経費、添付、月締め、メール認証ログイン
- 日次の保存（この変更は読み取りまで。保存は次の change で足せる）
- 深夜、休日出勤、日付をまたぐ時刻（現行は 35:00 まで）。このデモの時刻は同一日の時分
- 実在の社員名、給与、住所、生年月日
- コース本文への URL 追記。見本 URL は導入メモだけ

## リスク

- Lambda に同梱する SQLite は、このデモのダミー専用である。接続先を本番や開発 VM の MariaDB に読み替えると、実データが見える
- 学習用アカウントへのデプロイを、本番勤怠のアカウントと取り違えると、既存スタックに影響する
- スキルを Serena 必須にすると、Serena が未接続の環境では apply が止まる。止めるのがこのリポジトリの約束である

## 影響範囲

- 新規コードは `wizway-kintai-demo` のみ（`frontend/`、`backend/`、`sql/`、`template.yaml`、`.cursor/`）
- 学習パックの `導入メモ.md`（common と、ウィズウェイへ配っている版）に、見本 URL を1行足す。コース本文は変えない
- 本番勤怠の OpenSpec、ソース、AWS アカウントは変えない
