# Design

## Context

動機は proposal.md の Why。パスワードの組と、ログイン後も3人の一覧を残すことは proposal.md のスコープにある。

リポジトリは `wizway-kintai-demo`。画面は `frontend/`。API は `backend/app.py`。表は `sql/schema.sql` と `sql/seed.sql`。公開中の共有ファイルは、学習用アカウントの非公開 S3 にある `attendance.db`。各リクエストがダウンロードし、保存が成立したときだけ書き戻す。いまの CORS は GET と PUT だけである。

実装に入る前に、Serena MCP（namespace は `user-serena`）で `initial_instructions` を呼ぶ。失敗したらコードを編集しない。手順の正本は `.cursor/skills/openspec-apply-change/SKILL.md`。Serena の詳細は `docs/rules/project-rules-serena.md`。

## Goals / Non-Goals

**Goals:**

- 標準ライブラリだけでパスワードを照合し、セッションを共有ファイルに残す
- 既存の勤怠行を消さずに、パスワード列とセッションの表を足す
- 画面の入力者選択を、ログインした人に置き換える

**Non-Goals:**

- 署名用の秘密をリポジトリやテンプレートに書くこと
- 外部の認証サービス

## Decisions

### 1. パスワードはハッシュで持つ

`employees` にパスワードのハッシュとソルトを足す。照合は Python 標準の PBKDF2-HMAC-SHA256。平文は `sql/seed.sql` に書かない。`sql/build_db.py` が、proposal の3組からハッシュを入れて `backend/data/attendance.db` を作る。

開いた共有ファイルにハッシュ列が無いときは、行を残したまま列を足し、3人のハッシュを入れる。失敗したら書き戻さない。

代替として平文の列にする案は取らない。ログイン画面には出すが、ファイル上の値はハッシュにする。

### 2. セッションは共有ファイルの行にする

`sessions` に、ランダムなトークン、社員 id、期限を置く。期限は発行から8時間。トークンは標準ライブラリで作り、署名用の秘密は持たない。

ログインとログアウトが成立したときだけ、共有ファイルを書き戻す。パスワードが違うログインは書き戻さない。読み取りは書き戻さない。

画面はトークンを `sessionStorage` に置き、以降の要求の `Authorization` に `Bearer` で付ける。API Gateway と CloudFront は別のホストなので、Cookie にはしない。

### 3. 入力者はセッションの社員にする

更新の JSON に入力者があっても使わない。記録の入力者は、トークンの社員 id である。セッションが無い、または期限を過ぎているときは 401 とし、`reason` は「ログインしてください」。行も記録も書かない。

ログイン失敗の `reason` は「社員名かパスワードが違います」。ログにパスワードを出さない。

### 4. 画面はログインが先

トークンが無いときはログイン画面だけを出す。3人の表示名とパスワードを、proposal の組のとおり書く。成立したら今の一覧を出す。表示名と「ログアウト」を出す。入力者の選択は消す。保存の通信に入力者は付けない。401 のときはトークンを捨ててログイン画面に戻す。

`template.yaml` に `POST /login` と `POST /logout` を足す。CORS に POST を足す。

### 5. デプロイは学習用アカウントだけ

プロファイル `deploy-jisseki` で、アカウントが `655129713987` であることを確認してから `sam deploy` する。プロファイル `deploy` と、アカウント `023194178508` は使わない。スタック名は `wizway-kintai-demo`。画面は既存のフロント用バケットへ出す。公開 URL が変わっていなければ、学習パックの導入メモとコース本文は編集しない。

`openspec/specs/attendance-month/spec.md` の Purpose は、ログインしたセッションで読む文に直す。差分仕様では Purpose を変えられない。

## Risks / Trade-offs

- [ログインと保存が同じファイルへ重なる] → デモの範囲では、後から書き戻した方が残る。パスワード違いのログインでは書き戻さない
- [画面にパスワードが出る] → この3組はデモ用であり、秘密として扱わない
- [期限の8時間は画面を開いたまま過ぎることがある] → 401 でログイン画面に戻す

## Migration Plan

1. 表の拡張、ログイン、セッション必須、入力者の決定を API に足し、pytest で確認する
2. ログイン画面と、入力者の選択を外すことを足し、Playwright で確認する
3. `attendance-month` の Purpose を、ログインしたセッションで読む文に直す
4. アカウントを確認してから、学習用アカウントの API と画面を更新する
5. 公開 URL が変わっていないことを確認する。変わっていなければ導入メモは更新しない
6. 戻すときは、直前の関数と画面の成果物に戻す。共有ファイルのセッション表は残してよい
